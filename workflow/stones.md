# Подводные камни и накопленные знания

Файл хранит долгосрочную память о проблемах, ограничениях платформ и выводах, которые уже были
проверены. Модель может дополнять, сокращать и очищать его, когда знания устарели. Это не набор
постоянных правил: при конфликте действуют [CLAUDE.md](../CLAUDE.md) и
[rules.md](rules.md), а явное указание пользователя важнее любой записи здесь.

## Изоляция UI-проверки

2026-10-25. Пользователь может одновременно держать открытым собственный экземпляр MediaA.
Тестовая копия отделяется библиотекой `MEDIAA_DEV_LIBRARY` и уникальным
`MEDIAA_INSTANCE_ID`; без отдельного scope запуск может активировать пользовательское окно,
а проверка — изменить его данные. Снимок следует делать только окна тестового процесса по PID,
а после проверки завершать только этот PID. Пошаговая процедура — в
[practices.md](practices.md).

## Захват окон

- WGC отдаёт последний доступный кадр, не ожидая нового. Попытка синхронизировать ожидание с
  refresh может сбить темп записи.
- `xcap` может обрезать невидимые края окна; WGC отдаёт окно в видимых границах. Для снимков
  окон использовался WGC.
- Жёлтая рамка захвата скрывается на Windows 11, но может оставаться на старых версиях Windows.

## Платформы

- На Wayland четвёртый байт RGBx/BGRx в кадрах PipeWire не определён; нельзя полагаться на
  альфа-канал. Положением курсора управляет композитор.
- На macOS AVFoundation всегда рисует курсор, отключить его нельзя.
- Смещения региона задаются в пикселях монитора; на macOS виртуальный стол измеряется в points.
- X11 требует постоянного соединения и эффективного пути через MIT-SHM; попиксельная
  конвертация каждого кадра через `xcap` слишком медленная.

## UI и egui

- egui не сообщает нажатие PrintScreen; состояние клавиши нужно опрашивать через ОС.
- Скрытое или развёрнутое окно из трея надёжнее показывать нативно. Дочернее окно egui создаётся,
  только пока рисуется главное окно.
- Кнопка egui с рамкой только при наведении меняет размер на толщину обводки и сдвигает ряд.
  Для стабильной компоновки рамку рисуют вручную фиксированного размера.
- Вёрстка не должна прыгать: элементы занимают место заранее, соседние отступы берутся из одной
  константы, подсказки не имеют тени.

## WebP и FFmpeg

- FFmpeg декодирует только статичный кадр анимированного WebP; остальные кадры читаются через
  `image-webp`.
- `yuv420p` требует чётных сторон изображения; уменьшение не должно увеличивать кадр.
- При остановке FFmpeg `sink` обязан проглотить остаток и вернуть успех, иначе муксер может
  упасть на середине записи.
- Замена ручного WebP mux допустима только при совпадении поведения по alpha, timing и merge.

## Запись, время и файлы

- `pacer` выделяет кадру слот по активному времени записи. Опоздавший кадр оставляет дыру, ранний
  отбрасывается; аудиоукладка также должна сохранять общую временную шкалу.
- Старт захвата выполняется в фоне. Финализатор нельзя терять вместе с `JoinHandle`, а рабочие
  каталоги после сбоя нужно восстанавливать до очистки.
- Результаты и рабочие файлы публикуются через временный файл и атомарное переименование без
  перезаписи существующего результата.
- Настройки объединяются и записываются вне UI-потока; при выходе сохраняется последняя версия.
- У длительных пользовательских операций нет универсального wall-clock deadline. Время не
  доказывает зависание; нужны прогресс, отмена или подтверждённый liveness-механизм.

## Кэш библиотеки

`HitList` кэшируется до изменения версии индекса, query или limit. Обновление details обязано
менять версию индекса, иначе UI покажет старые metadata.
