# Правила проекта

Этот файл содержит только правила, которые разработчик явно зафиксировал в процессе работы.
Модель не повышает собственные выводы до правил без прямого указания пользователя. Общие
инженерные правила проекта остаются в [CLAUDE.md](../CLAUDE.md), чтобы не дублировать их здесь.

## UI-проверка

- Проверять UI только в отдельной тестовой копии приложения.
- Для тестовой копии задавать отдельную библиотеку через `MEDIAA_DEV_LIBRARY` и отдельный scope
  single-instance через уникальный `MEDIAA_INSTANCE_ID`.
- Можно открывать нужную страницу через `--page=library`, `--page=record`, `--page=audio`,
  `--page=convert`, `--page=settings` или `--page=about`.
- Запрещено взаимодействовать с пользовательским экземпляром MediaA, менять его состояние или
  завершать его процесс.

## Безопасность

- Не отправлять глобальные нажатия клавиш. `SendKeys` запрещён; `PostMessage` допустим только
  для собственного окна.
- Не управлять чужими окнами и не снимать их содержимое.
- Не завершать чужие процессы. Останавливать можно только процесс, запущенный для текущей
  проверки, по известному собственному PID.

## Проверки кода

- Не повторять Rust-тесты, если код не менялся после последнего успешного прогона.
- Изменения, внесённые только форматированием, не считаются изменением кода для решения о
  повторном запуске тестов.
- Если код не менялся, выполнять только проверки, относящиеся к фактически изменённым файлам и
  поведению.
