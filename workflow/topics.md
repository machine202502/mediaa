# Темы видео — проект

Проект задачи «Темы видео» (бывшая 6.1, закрыта — [done.md](done.md); оценка качества — 6.2 в [todos.md](todos.md)). Что сейчас в работе — [process.md](process.md);
справочник — [dev-context.md](dev-context.md). Контракт для подзадач: код пишется по нему, расхождения
сначала правятся здесь.

## 1. Данные (контракт между алгоритмом и интерфейсом)

* Тема — `mediaa_core::outline::Chapter { start, end, digest }` в таблице `chapters` базы записи
  (как сейчас; одна строка — одна тема, по порядку, без пересечений, покрывают запись от первой до
  последней реплики).
* `Digest`: `title`, `summary`, `decisions`, `actions`, `questions`, `topics` (как сейчас) и новое
  `parts: Vec<Part { start, end, title }>` — подтемы длинной темы (пусто у обычной);
  `quotes: Vec<Quote { time, text }>` — 0–3 ключевые реплики темы словами говорящих, время каждой —
  время реальной реплики (проверяется). Поля JSON-а главы — без изменения схемы базы (данные в
  колонке `data`); старые главы без `quotes` читаются (`serde(default)`).
* Интерфейс читает только это; алгоритм может меняться, не трогая интерфейс.

## 2. Алгоритм (задача `outline`, `crates/agent/src/outline.rs`)

1. **Кандидаты в границы по смыслу.** Эмбеддинги чанков уже есть после индексации
   (`chunks.embedding`). Для каждой границы между чанками — сходство среднего эмбеддинга `k` чанков
   слева и справа (k = 2–3); «глубина провала» как в TextTiling; границы — где глубина выше порога
   (среднее + 0.5·σ по записи). Минимальная длина темы — 2 минуты речи (короче — сливается с соседом
   с большим сходством). Без эмбеддингов (модель эмбеддингов не задана) — окна по
   `WINDOW_WORDS`, как сейчас.
2. **Сводка темы.** Тема короче окна (`WINDOW_WORDS`) — одна сводка по её тексту. Длиннее — сводки
   частей по окнам, затем одна сводка темы из сводок частей (map-reduce). Выдержки (`quotes`) —
   модель выбирает из строк текста темы `[m:ss] Имя: текст`; время каждой проверяется по репликам
   (ближайшая реплика с совпадением слов), непроверяемые отбрасываются.
3. **Склейка — итеративно, решает код, модель — только для пограничных случаев.** Объединённые
   темы получают сводку из сводок (reduce), без повторного чтения текста. (Живой прогон
   2026-10-21: модель 4B, получив весь список, склеила все 5 тем видео в одну; на часовых роликах
   бывало 4 одинаковые темы подряд.)
   * повторять: склеить самую похожую пару соседей, пересчитать сходство объединённой темы — пока
     есть пары выше порога (4 одинаковые подряд сливаются за 3 шага);
   * сходство пары — из двух признаков: средние эмбеддинги чанков тем и эмбеддинги их описаний
     («название + сводка»);
   * пороги — из распределения сходств самой записи: явно похожие склеиваются кодом, явно разные —
     нет, промежуточные — вопрос модели про одну пару: «продолжение той же темы или новая?» (JSON);
   * без минимума числа тем; каждое решение (сходства, кто решил, итог) — в лог.
   **Подтемы:** тема длиннее 15 минут после склейки хранит свои исходные куски как подтемы
   (`Digest.parts: Vec<Part { start, end, title }>`), в блоке тем они раскрываются внутри темы.
4. **Возобновление.** Задача очереди продолжает с места: план границ хранится в `meta` записи
   (`outline-plan`), сводки — по одной теме (как сейчас по одной главе), склейка — отдельный этап
   курсора.
5. Все промпты — шаблоны `crates/agent/prompts/outline/*.j2` (CLAUDE.md), JSON — по грамматике.
6. Язык — язык записи (до задачи 3.2 о языке интерфейса).

## 3. Интерфейс

* **Таймлайн плеера** (полоса перемотки в студии): сегменты тем с зазором 2 px; под курсором
  сегмент подсвечивается, подсказка — название, «m:ss–m:ss», первая строка сводки. Клик по полосе
  перематывает туда, куда кликнули (как обычный плеер); к началу темы — из блока тем.
* **Блок тем вверху панели «Диалог»**, закреплён (не прокручивается с репликами):
  * свёрнут — одна строка: текущая тема «m:ss Название (3/7)», где сейчас плеер;
  * развёрнут — список всех тем (время + название, текущая выделена), не выше ~40 % панели,
    своя прокрутка; у темы раскрывается сводка: summary, решения, задачи, вопросы, выдержки
    (клик по выдержке — переход к её времени);
  * клик по теме — диалог прокручивается к её первой реплике, плеер переходит к её началу;
  * состояние «свёрнут/развёрнут» запоминается.
* Карточки глав внутри потока реплик убираются.
* Тексты — в локалях ru и en.

## 4. Проверка

* Юнит-тесты: границы (синтетические эмбеддинги с явными провалами), минимальная длина, склейка
  по ответу модели (подставной движок `mediaa_engine::testing::FakeEngine`), проверка выдержек.
* Живая проверка (голова): видео пользователя (27 мин) и Лукоморье — число тем и названия
  до/после (сейчас по видео — окна по 1200 слов), нет соседних тем с одним смыслом.
