## 1. Проект в двух словах

* **MediaA** — настольное приложение на Rust: egui 0.36 + wgpu, Windows в первую очередь.
  Выпуск — **одна программа** `mediaa` (UI, захват, конвертация; один статический exe с FFmpeg);
  движок моделей (`mediaa_engine`) — библиотека внутри неё, приложение зовёт его напрямую
  (контракт — [engine.md](engine.md)). Разделы приложения: Библиотека, Захват, Конвертация, Агент.
* Раздел **Агент**:
  * каталоги аудио и видео, у каждого файла вкладка-«студия» с панелями Диалог · Видео · Чат;
  * распознавание речи и диаризация — в движке (sherpa-onnx), приложение передаёт ему PCM в памяти;
  * гибридный поиск по записи (FTS5 + эмбеддинги + реранкер);
  * главы со сводками (outline);
  * чат с агентом-инструментальщиком по одной записи или по папке;
  * поиск в интернете.
* Пользователь общается **по-русски**, ответы — по-русски. Интерфейс тоже на ru/en: оба
  языка в `crates/app/locales/{ru,en}.toml`, каждый ключ должен быть в обоих.
* **Правила проекта ([CLAUDE.md](../CLAUDE.md)):**
  * никакой обратной совместимости: ни миграций, ни шимов, ни версий настроек;
  * неиспользуемое удалять, включая ключи локализации;
  * предпочитать зрелые крейты;
  * всё покрывать тестами;
  * перед завершением прогонять `cargo test --workspace` и
    `cargo clippy --workspace --all-targets`;
  * все тексты для модели — в шаблонах `crates/agent/prompts/**/*.j2` (см. раздел 4).
* **Ограничения от пользователя:**
  * не слать глобальные нажатия клавиш (SendKeys запрещён), PostMessage — только своим окнам;
  * не убивать чужие процессы: только свои PID, например записанный в `/tmp/mediaa.pid`;
  * не смотреть чужие окна;
  * установка ПО — только с разрешения;
  * API-ключи хранятся в системном хранилище паролей (крейт `keyring`, `core::secrets`),
    никогда в `settings.toml` или файлах;
  * email пользователя никуда не отправлять.
* На вопрос «объясни» сначала отвечать текстом: **на вопрос — ответ, код — только по согласию**.

## 2. Сборка, запуск, тесты

```bash
export VULKAN_SDK="C:/VulkanSDK/1.4.363.0"
export LIBCLANG_PATH="C:/Program Files/Microsoft Visual Studio/18/Community/VC/Tools/Llvm/x64/bin"
cargo build --release -p mediaa
cargo test --release --workspace
cargo clippy --release --workspace --all-targets
```

* llama.cpp (`llama-cpp-2` 0.1.159) собирается с Vulkan в крейте движка (`crates/engine`),
  `vulkan-1.dll` подгружается отложенно через `crates/app/build.rs` (это флаг линковки бинаря
  `mediaa`); приложение запускается и без него, тогда модели идут на процессоре
  (`mediaa_engine::llm` сначала проверяет загрузчик).
  Файл `Directory.Build.targets` (`BuildInParallel=false`) лечит гонку MSBuild
  в `vulkan-shaders-gen`, удалять его нельзя.
* FFmpeg — статический, через vcpkg (`x64-windows-static-release`), `+crt-static`.
* В Git Bash нет Python (только заглушка Windows Store). Многострочные правки Rust делать
  через Edit: perl и sed портят `\n`, `\\` и `@{}`.

### Запуск для проверки UI

```bash
# движок внутри приложения: отдельный процесс не нужен. Модели — в папке данных приложения
# (paths::models_dir(): Windows %LOCALAPPDATA%\MediaA\MediaA\data\models); тестам её задаёт
# MEDIAA_TEST_MODELS. Пустая папка — нормально: страница «Модели» скачает выбранные.
S=<scratchpad>; MEDIAA_DEV_LIBRARY="$S/lib" ./target/release/mediaa.exe --page=queue & echo $! > /tmp/mediaa.pid
cargo run --release -q -p mediaa-platform --example snap -- "$S/out.png" MediaA
kill $(cat /tmp/mediaa.pid)
```

* `scripts/ui-snap.sh` собирает и запускает приложение на тестовой библиотеке: движок уже
  внутри него, чип в шапке показывает «Движок работает».
* `--page=` принимает library, record, providers, queue, budget, models, catalogs и другие
  страницы (см. `page_from_args` в `app.rs`).
* `MEDIAA_DEV_OPEN` открывает файл, а если передать имя папки — чат этой папки.
* `MEDIAA_DEV_ASK` один раз задаёт вопрос в открытом чате.

Пользователь сам запускает **debug**-сборку `target\debug\mediaa.exe` со своей библиотекой
`C:\Users\wmachine\Documents\MediaA`. Его процессы не трогать.

Настройки пользователя: `%APPDATA%\MediaA\MediaA\config\settings.toml`. Старые значения
моделей из ранних версий там могут остаться (`Qwen/Qwen3.5-4B`, `istupakov/gigaam-v2-onnx`).
По правилам проекта их не мигрировать: кнопка ↺ в «Моделях» возвращает умолчание.

### Бенч агента на реальной модели (игнорируемый тест)

```bash
MEDIAA_BENCH_LIB=<библиотека> MEDIAA_BENCH_FILE=<видео> \
MEDIAA_BENCH_QUESTIONS='вопрос 1|вопрос 2' \
MEDIAA_BENCH_TAVILY=<ключ, только через env> MEDIAA_BENCH_PROXY='socks5h://127.0.0.1:10901' \
cargo test --release -q -p mediaa-agent bench_on_a_recording -- --ignored --nocapture
```

* Все живые (игнорируемые) тесты агента — бенч, `transcribe`, `outline`, `assistant` — сами
  создают `LocalEngine` на папке моделей `MEDIAA_TEST_MODELS` (по умолчанию
  `paths::models_dir()` — папка приложения) под бюджетом по умолчанию (`crates/agent/src/live.rs`).
  Отдельный процесс движка не нужен; недостающие модели тест скачает сам.

* Флаги: `MEDIAA_BENCH_OUTLINE=1` пересобирает главы, `MEDIAA_BENCH_FOLDER=1` задаёт вопросы
  по всей библиотеке.
* Живой веб-тест: `cargo test -p mediaa-agent searches_and_reads_the_web -- --ignored`, с теми
  же переменными `MEDIAA_BENCH_TAVILY` и `MEDIAA_BENCH_PROXY`.
* **Сеть:**
  * DuckDuckGo с этого IP требует капчу;
  * Tavily без прокси отвечает 403 (блокировка сети ещё до проверки ключа);
  * с прокси пользователя `socks5h://127.0.0.1:10901` всё работает;
  * ключ Tavily в файлы не писать: передавать через env или вводить в приложении
    («Агент → Провайдеры → Поиск в интернете → Tavily»), где он уходит в keychain.
* Модель агента по умолчанию — `unsloth/Qwen3.5-4B-GGUF` на встроенной видеокарте. Ответ идёт
  от 30 с до 5 мин, скан всей записи дольше.

## 3. Как работаем

* **Роли.**
  * **Голова** — модель, с которой общается пользователь; какая именно — неважно,
    пользователь выбирает её сам. Голова продумывает решение, пишет самодостаточное задание
    и проверяет результат (дифф, тесты). За ней же — решения, которые требуют контекста
    разговора, и вопросы к пользователю.
  * **Подагенты** — реализуют. Какой модели дать задачу, решает голова.
  * **Голова следит за архитектурой и делегирует.** Нашла ошибку или решение можно лучше —
    возвращает задачу исполнителю (`scripts/subagent.sh resume` в его сессии) или новому подагенту,
    а не правит сама. Сама правит только в крайнем случае (критичный код) или когда пользователь
    просил всё провалидировать. Её ресурс — архитектура, структура файлов и то, как решения
    подагентов сочетаются с другими задачами.
* **Цель — экономия денег пользователя.** Простое, что дешевле сделать самому, чем писать
  задание и проверять, голова делает сама. Остальное — самому дешёвому подагенту, который
  справится хорошо.
* **Модели подагентов, которые можно вызывать:**
  * Haiku — механика по образцу (штатный подагент Claude Code, тратит лимиты Claude).
  * Sonnet — задачи средней сложности с ясной постановкой (штатный, тратит лимиты Claude).
  * DeepSeek V4.1 Flash (`deepseek-flash` в API DeepSeek) — через скрипт, см. ниже. Дешевле
    Haiku, пишет код хорошо; лимиты Claude не тратит (платится с баланса DeepSeek; ключ —
    `~/.secrets/deepseek.key` или `DEEPSEEK_API_KEY`). Можно запускать
    несколько параллельно, если они не трогают одни файлы.
* Задание подагенту самодостаточное: пути, правила CLAUDE.md, точные ожидаемые тексты,
  команды тестов, «не коммитить, не менять git-индекс, не запускать приложение и не убивать
  процессы», «строки с `\` и `\n` править инструментом Edit, а не sed/perl».
* Подагентов, трогающих одни файлы, запускать по очереди. Git worktree начинается с HEAD,
  поэтому незакоммиченную работу он не видит.
* Тесты гонять один раз в конце работы (сборка долгая), а не после каждой правки.
* **Уведомление пользователя.** Когда вся задача готова или голова ждёт решения пользователя —
  push-уведомление (`PushNotification`) с началом «ГОТОВО:» или «НУЖНЫ ВЫ:». Обычные баннеры
  приложения приходят при каждом конце ответа (и пока голова ждёт подагентов), поэтому значат
  только «что-то изменилось». В приложении включены баннеры со звуком и мигание кнопки на
  панели задач (`draw_attention_on_notifications`).
* Коммитить только по явному разрешению пользователя, каждый раз отдельно (глобальное правило
  в `~/.claude/CLAUDE.md`).

### Подагенты на DeepSeek

* Запуск: `scripts/subagent.sh [--provider deepseek|openrouter] [--model ID] [--max-turns N] TASK_FILE`.
  Задание — в файле (команда должна начинаться с `scripts/subagent.sh`: на это стоит правило
  разрешения в `.claude/settings.local.json`). Ответ — JSON Claude Code, итог в поле `result`.
* Подагент — безголовый Claude Code с моделью DeepSeek: те же правила проекта (CLAUDE.md),
  чтение и правка файлов, `cargo`, команды чтения, `git diff/status`, `WebFetch`, браузер VS Code
  (`mcp__integrated-browser-mcp`) и отладчик (`mcp__debugmcp`). Запрещено: `git commit/add/reset/
  push/stash/checkout/restore/rm`, скриншот экрана (`desktop-mcp`), Chrome пользователя.
  Всё прочее отклоняется (спросить некого).
* `total_cost_usd` в ответе посчитан по ценам Anthropic — неверно; настоящая — в `cost-*`
  (см. «Стоимость» ниже; порядка десятых долей цента за короткую задачу). Провайдер по
  умолчанию — прямой API DeepSeek; `--provider openrouter` — запасной (ключ
  `~/.secrets/openrouter.key`, сейчас удалён).
* Скрипт снимает переменные `CLAUDE*`/`ANTHROPIC*`, унаследованные от приложения Claude:
  иначе дочерний `claude` ждёт ключ от хозяина и шлёт запросы без ключа (401).
* Браузер VS Code работает в полном режиме (`argv.json`: `enable-proposed-api` для
  `thimo.integrated-browser-mcp`): у каждого агента своя вкладка — открывать через
  `browser_tab_open` и передавать её `tabId`. `browser_screenshot` возвращает только картинку,
  в файл не сохраняет: для артефакта — `desktop-mcp` `capture_screenshot` с `region` и `savePath`.

### Журналы подагентов (`subagents/`)

* Каждый подагент — свой файл `subagents/<дата_время>_<модель>_<задача>.md` (папка в
  `.gitignore`): задание, статус (`работает` / `готово` / `ошибка`), ход работы (мысли, тексты,
  вызовы инструментов с результатами), итог. Пользователь смотрит туда, что делают подагенты.
* Пишет их [../scripts/subagent-log.mjs](../scripts/subagent-log.mjs):
  * `watch` — зеркалит всё, что меняется (запускается сам хуком при старте сессии, см. ниже);
  * `once` — разово перерисовать всё;
  * `follow RUN_DIR` — один запуск `scripts/subagent.sh` (скрипт делает это сам).
* Источники: штатные подагенты Claude Code —
  `~/.claude/projects/<проект>/<сессия>/subagents/agent-*.jsonl` (+ `.meta.json` с описанием
  и моделью); запуски DeepSeek — `target/subagents/<запуск>/stream.jsonl`.
* У запусков DeepSeek давать понятное имя: `scripts/subagent.sh run --name "7.1 Вкладки …" TASK_FILE`,
  у штатных — поле `description` при запуске.
* Команды `scripts/subagent.sh status RUN_DIR` (сколько работает, жив ли процесс, последний шаг)
  и `resume RUN_DIR MESSAGE_FILE` (продолжить ту же сессию: вопрос, уточнение, «продолжай»).
  Запуск — всегда в фоне: у фоновых команд нет лимита в 10 минут.

### Реестр, PID и восстановление

* `subagents/registry.md` — строка на каждый запуск, пишется **при старте**: время, задача,
  модель, процессы (PID Git Bash и Windows для DeepSeek; сессия головы, PID Claude Code
  и идентификатор агента для штатных), сессия, папка запуска / журнал. Строки DeepSeek пишет
  `scripts/subagent.sh`, штатных — зеркало `subagent-log.mjs`.
* `scripts/subagent.sh list` — все запуски DeepSeek: `running`, `finished: …` или
  `GONE without a result` (процесс пропал без итога — сбой; продолжить: `resume RUN_DIR MESSAGE_FILE`).
* В папке запуска `target/subagents/<запуск>/`: `task.md`, `name`, `model`, `provider`, `started`,
  `pid`, `winpid`, `script_pid`, `log_pid`, `session_id` (сохраняется через секунды после старта),
  `stream.jsonl`, `stderr.log`, `result.json`, `artifacts`.
* Если упал сам Claude Code: процессы DeepSeek, вероятно, завершатся вместе с ним, но сессия на
  диске — `resume` продолжит её. Штатные подагенты живут в процессе головы: после падения
  остаётся их полный журнал, недоделанное перезапускается новым заданием.

### Артефакты и проверка результата

* Нужна ли подагенту проверка с доказательствами, решает голова по выгоде: дешевле проверить
  самой (одна команда, один скриншот) — не требует; иначе требует.
* Одно имя на всё, что относится к запуску: `<дата_время>_<модель>_<задача>` — лог
  `subagents/<имя>.md`, артефакты `subagents/artifacts/<имя>/`, у DeepSeek ещё папка запуска
  `target/subagents/<имя>/` и строка в реестре. Имя строит `subagent-log.mjs id`. Штатному
  подагенту голова называет папку артефактов в задании; когда он закончит, зеркало
  переименует её под имя лога.
* Папку артефактов для DeepSeek создаёт скрипт и сам
  дописывает к заданию памятку (функция `artifacts_note` в `scripts/subagent.sh`); штатным
  подагентам голова вставляет такую же памятку в задание.
* Состав: `report.md` (что сделано, как проверено со ссылками на файлы, решения и почему —
  особенно отступления от задания, открытые вопросы) и доказательства: скриншоты, нужный кусок
  вывода тестов/clippy/команд, замеры. Мысли подагента не дублировать — они уже в логе.
* Скриншоты:
  * окно MediaA — **только** [../scripts/ui-snap.sh](../scripts/ui-snap.sh) `OUT.png [--page NAME]
    [--open NAME_PART] [--library DIR]`: собирает, запускает свою копию на тестовой библиотеке,
    снимает только окно этой копии (по PID, `snap … pid:N`), закрывает её. Самим запускать
    приложение подагентам нельзя (`cargo run` запрещён в скрипте DeepSeek);
  * веб-страница — своя вкладка браузера VS Code; `browser_screenshot` в файл не сохраняет;
  * сохранить снимок с экрана — `desktop-mcp` `capture_screenshot` с `region` и `savePath`,
    никогда не весь экран.
* Модели DeepSeek не могут надёжно написать тег `<think>` (для них это начало собственных
  рассуждений): задачи, где в коде или тексте есть `<think>`, — Sonnet/Haiku, либо предупредить в
  задании не трогать такие строки.
* Отказ в команде или инструменте — не обходить, а написать в отчёте (DeepSeek на тесте пытался
  обойти запрет и запустил приложение через `cargo run` на настоящей библиотеке пользователя).

### Изменения, стоимость, архив, автозапуск

* **Что поменял запуск.** До и после каждого `run`/`resume` скрипт снимает хэши всех файлов
  проекта (без игнорируемых) и базу `git stash create` (git при этом не меняется). Итог —
  `changes-<run|resume-…>.patch` в папке запуска и в артефактах: добавленные, изменённые,
  удалённые файлы с диффом. Правки параллельного запуска тоже попадут — это помечено в файле.
* **Стоимость.** Токены из итога запуска × цены модели из публичного списка OpenRouter
  (`token_cost`; модели API DeepSeek сопоставлены с той же моделью в списке OpenRouter);
  счётчик расходов по ключу (OpenRouter — с задержкой, баланс DeepSeek — до центов) служит только
  запасным способом. Пишется в `cost-<…>`, видна в итоге запуска, в шапке лога и в `list`.
* **Архив.** Завершённый запуск, журнал которого не менялся дольше срока, зеркало переносит
  в `subagents/archive/` (лог) и `subagents/archive/artifacts/` (артефакты), ничего не удаляя.
  Срок — `subagents/config.json` → `archiveAfterHours` (по умолчанию 6), переменная
  `SUBAGENT_ARCHIVE_HOURS` важнее. Запуск, продолженный через `resume`, возвращается из архива.
  `registry.md` не архивируется.
* **Лимит ходов.** Запуск, остановленный на `--max-turns`, имеет статус «остановлен на лимите
  ходов», а в итоге лога — готовая команда `resume`.
* **Автозапуск зеркала.** Хук `SessionStart` в `.claude/settings.local.json` выполняет
  `node scripts/subagent-log.mjs watch --detach`: наблюдатель запускается в фоне при старте
  каждой сессии Claude Code в проекте; второй не запустится (PID в `subagents/.watch.pid`).

## 4. Система шаблонов промптов

Все тексты, которые уходят модели (системные промпты, задания, описания инструментов,
корректирующие сообщения, результаты и ошибки инструментов), лежат в MiniJinja-шаблонах
`crates/agent/prompts/**/*.j2`. Вся папка встраивается в бинарь через `minijinja-embed` в
`crates/agent/build.rs`. Рендер — `prompts::render(name, ctx)`, описания инструментов —
`prompts::tool(name)` (модуль `crates/agent/src/prompts.rs`). Окружение строгое
(`strict undefined`), включены `trim_blocks` и `lstrip_blocks`; условия и составные части
живут в шаблоне (`{% if %}`, `{% include %}`), код передаёт только данные. Тексты проверяются
снапшотами insta (`crates/agent/src/snapshots/`) и точными тестами в `prompts.rs`.
Для `.j2` и `.snap` в `.gitattributes` закреплён LF. Любая правка промпта делается в `.j2`,
а её снапшот просматривается. В Rust остаются только внутренние ошибки, которые модель не
видит (например, «the step is not JSON» в `brain.rs`, по которой цикл узнаёт обрезанный шаг).

## 5. Подводные камни, на которые уже наступали

* Маленькая модель путает `search` (по записи) и `web_search`. Описания инструментов и
  правило в промпте это уже различают. Не ослаблять.
* Большая страница из `web_read` вытесняла из контекста результаты скана, отсюда ответы
  «в видео ничего нет». Отсюда лимит `max_chars / 3` в `Web::new`.
* Первый шаг агента всегда смотрит в запись (`may_answer=false`); ответ — первый вариант
  `oneOf` в грамматике.
* Цикл генерации гасят DRY-сэмплер (разрывает только `"\""`) и `loop_start`. Обрезанный шаг
  повторяется до 2 раз.
* Скан кешируется в мета-данных записи под ключом `scan2:{parts}:{instr}`. Если менять
  формат скана, менять и ключ.
* В чате по папке голые длительности не превращаются в ссылки (`bare_times=false`).
* Загрузки с HF идут по одной (глобальный мьютекс). Спецификация `owner/repo/path/file`
  скачивает один файл.
