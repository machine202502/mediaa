# Ограничения MediaA

Здесь собраны ограничения, которые влияют на решения человека и LLM. Это не инвентарь всех
особенностей кода: запись добавляется, когда повторная ошибка или изменение без учёта этого факта
может ухудшить продукт.

## Изоляция UI-проверок

Пользователь может одновременно держать открытым рабочий экземпляр MediaA. Поэтому тестовая
копия обязана иметь отдельную библиотеку и отдельный single-instance scope. Иначе проверка может
активировать пользовательское окно или изменить его данные.

## Захват окон

- Windows Graphics Capture отдаёт последний доступный кадр и не синхронизируется с refresh.
  Ожидание нового кадра может сбить темп записи.
- `xcap` может обрезать невидимые края окна. Для оконных снимков использовался WGC.
- Жёлтая рамка WGC скрывается на Windows 11, но может оставаться видимой на старых версиях.

## Платформы

- Wayland/PipeWire не гарантирует содержимое alpha-байта в RGBx/BGRx. Курсором управляет
  композитор.
- macOS AVFoundation всегда рисует курсор.
- Регионы монитора задаются в pixels, но виртуальный desktop macOS измеряется в points.
- X11 для производительности требует постоянного соединения и MIT-SHM; попиксельная
  конвертация через `xcap` слишком медленная для записи.
- Linux/macOS live tests не покрываются обычным Windows-прогоном и требуют отдельной среды.

## UI и egui

- egui не сообщает PrintScreen как обычное нажатие; состояние нужно опрашивать через OS.
- Скрытое или развёрнутое native-окно из трея нужно показывать нативно.
- Рамка только при hover меняет размер widget и сдвигает layout. Для устойчивой компоновки
  обводка рисуется вручную с фиксированным размером.
- Вёрстка не должна прыгать: placeholders, единые отступы и отсутствие теней у hints.
- Ручной clickable widget должен публиковать `WidgetInfo`, иначе AccessKit и `egui_kittest` его
  не увидят.
- `kittest.toml` задаёт snapshot path относительно crate root. Для `mediaa` это
  `tests/snapshots`, фактически `crates/app/tests/snapshots`.
- Глобальные горячие клавиши по умолчанию выключены. Включение — явное действие пользователя;
  уже сохранённое `enabled = true` остаётся в силе до выключения.
- «При запуске открывать в трее» доступно только при включённом автозапуске. При
  `launch_at_login = false` поле `start_in_tray` сбрасывается при загрузке настроек.
- В region editor annotations и text не ограничены selection. Shapes хранятся в pixels полного
  кадра, поэтому сдвиг или resize selection не теряет их. В итоговый файл попадает только часть
  внутри выбранного crop.
- Активный text ещё не входит в committed shapes. Его рамка является границей editing: drag полей
  двигает text origin, клик снаружи фиксирует shape. Перетаскивание рамки не должно завершать
  editing, и клик, завершивший текущий text, не должен сразу открывать следующий editor. Рамка не
  добавляет подложку, а commit использует фактический rendered origin текста, чтобы shape не
  смещалась после применения. `Shift+Enter` добавляет новую строку и не завершает editing.
- Selection size badge нельзя размещать поверх активного text frame. Нужно выбирать другую позицию
  вокруг selection или внутри свободного угла, сохраняя badge в границах display.
- `Tab` в region editor не должен создавать новый native overlay viewport или запускать второй
  monitor capture. Пока кадр следующего монитора не готов, повторный `Tab` игнорируется. Ошибка или
  timeout capture обязаны снять switching state, иначе скрытый `Overlay` блокирует tray/UI actions.
  ViewportBuilder обязан отражать текущее `shown`: постоянный `visible(false)` скрывает уже
  существующий стабильный viewport после первого показа. При одном мониторе `Tab` является no-op;
  при нескольких мониторах порядок строго следует списку monitors, включая ещё не захваченные.
- Сохранение из region overlay открывает системный диалог папки, имени и формата. На время диалога
  viewport переводится в `WindowLevel::Normal` и потом обратно в `AlwaysOnTop`, иначе диалог
  оказывается под полноэкранным оверлеем. Оверлей закрывается только после успешной записи; отмена
  диалога оставляет его открытым.
- Опции «После снимка» не настраиваются: формат PNG, действие «копировать и сохранить», окно
  всегда скрывается. Снимок области, полного экрана и окна планируется с `hide = true`, затем
  `HIDE_DELAY`, и только после этого снимается кадр; иначе окно попадает в снимок.
- Завершённая запись всегда копируется в буфер как файл и попадает в библиотеку. Выбора
  «библиотека или буфер» нет.
- «Скрывать в трей во время записи» настраивается только для записи из окна программы. У
  профилей хоткея и региона такой опции нет: они и так запускаются из трея или с клавиатуры.
  Перед стартом записи окно скрывается, затем `HIDE_DELAY`, затем начинается запись.
- Кнопка «Копировать» и Enter в region overlay всегда делают два действия: сохраняют PNG в
  библиотеку и копируют изображение в буфер (`AfterCapture::CopyAndSave`).
- «Контракт расшифровки» открывается иконкой информации у пункта «Расшифровка» в меню добавления
  провайдера. На странице «О программе» отдельной кнопки нет.
- «Показывать прогресс в трее» включено по умолчанию. Выключение убирает цветную точку статуса
  и состояние из подсказки трея, оставляя обычную иконку MediaA.
- Снимок области и выбор области записи, запущенные из интерфейса, возвращают главное окно после
  закрытия оверлея (копирование, сохранение, отмена, выбор области).
- Любое действие трея, кроме явного «Открыть окно», не скрывает, не показывает и не поднимает
  главное окно: запись экрана/аудио, стоп, отмена, снимок области, полноэкранный снимок, выбор
  региона. Хоткей и CLI `--area` по-прежнему скрывают окно для захвата.
- Пока запись не `Idle`, страницы «Запись» и «Запись аудио» показывают цели, настройки и запуск,
  но неактивными. Снимки при этом работают. Иконка трея не реагирует на capture/clipboard, только
  на запись и фоновую обработку.
- Открытая модалка блокирует мышь и клавиатуру всего интерфейса, включая уведомления; фон
  остаётся нарисованным без затемнения. Закрыть модалку можно только её средствами.
- Каналы результатов WebP-воркеров (`live_webp`, segmented scheduler) должны быть unbounded:
  ограниченный канал плюс `join` после выхода из цикла приводят к вечному `Saving`.
- Live WebP fallback решается по каждому источнику: сбой одного источника не переводит остальные
  с live-пути на offline. Общая ошибка `LiveResult` не используется.
- Запись, запущенная из трея (экран или аудио), не скрывает и не показывает окно. UI-запись и
  хоткеи по-прежнему используют `hide_to_tray` профиля.
- `scripts/windows/run.ps1` сам снимает блокировку со сценариев и при падении сборки один раз
  сбрасывает кэш `ffmpeg-sys-next` и повторяет сборку; `run.cmd` запускает его без запроса
  политики выполнения.
- Region overlay создаётся скрытым заранее с постоянным ID и без изменения `active`. При подключении
  реального UI нужно явно запросить repaint root и overlay viewport; prewarmed viewport не получает
  неявный initial repaint нового окна. Использовать `with_fullscreen(true)` для этого viewport
  нельзя: на текущем egui-wgpu он воспроизводимо падает в staging buffer.

## WebP и FFmpeg

- FFmpeg декодирует только статичный кадр animated WebP; остальные кадры читает `image-webp`.
- `yuv420p` требует чётных размеров. Уменьшение изображения не должно его увеличивать.
- При остановке FFmpeg sink должен вычитать остаток и завершиться успешно, иначе muxer может
  упасть в середине записи.
- Ручной WebP merge нельзя заменять библиотекой без совпадения alpha, timing и segment merge.
- FFmpeg process abort/OOM не превращается в обычный `Result` через `catch_unwind`.
- OOM или resource failure нельзя определять по тексту сообщения. Без typed signal неизвестная
  ошибка сохраняет прежний bounded retry.
- `MemoryBudget` — расчётная защита сегментов, а не измерение или жёсткий лимит RSS.

## Record timing и файлы

- Pacer выделяет кадру слот по активному времени записи. Поздний кадр оставляет дыру, ранний
  отбрасывается. Аудио должно следовать той же шкале.
- Capture start выполняется в фоне.
- Finalizer нельзя терять вместе с `JoinHandle`; `Saving` удерживает его до terminal event.
- После сбоя recovery sources должен выполняться до очистки рабочего каталога.
- Файлы публикуются атомарно и без перезаписи существующего результата.
- Настройки объединяются и записываются вне UI; при выходе сохраняется последняя версия.
- У длительных операций нет универсального wall-clock deadline. Время не доказывает зависание;
  нужны progress, cancel, liveness или deadline конкретного внешнего ресурса.

## Clipboard и SettingsWriter

- Native clipboard может зависнуть из-за другого приложения. Timeout ограничивает ожидание, а
  worker restart возвращает сервис в рабочее состояние.
- Timeout не доказывает отмену OS side effect. Уже принятая операция может завершиться позже.
- Синхронная запись каждого изменения настроек блокировала бы UI на медленном диске.
  `SettingsWriter` объединяет изменения и сохраняет последнюю версию.
- `settings.toml` сохраняется независимо от OS keychain: ключи провайдеров синхронизируются
  best-effort после записи файла, иначе недоступный keychain терял бы все настройки.
- Удаление этих защит требует воспроизводимого fault-injection на отдельной VM/session.

## Уведомления

- Уведомления имеют appearance/closing animation и всегда получают конечный срок жизни.
  Раскрытие меняет размер карточки, но не делает её вечной.
- Пока указатель находится над карточкой, оставшийся lifetime приостанавливается. После выхода
  отсчёт продолжается с сохранённого остатка.
- Действия внутри уведомления не создают новых уведомлений. Копирование использует silent
  clipboard purpose; ошибки пишутся в лог. Reveal из уведомления также подавляет notice об ошибке.

## Library index

- Источник пользовательских файлов — каталог. SQLite, thumbnail atlas и preview proxies
  перестраиваемы.
- `HitList` кэшируется по version, query и limit. Обновление details обязано менять version.
- Watcher может потерять события или переполниться. Overflow уже требует полного reconciliation.
- Локальный benchmark на NTFS:
  - 50k scan p50 около 157 ms, p95 около 187 ms;
  - `apply_scan` около 54–63 ms на UI-потоке;
  - burst изменений может дать overflow и последующий rescan.
- Периодический rescan сохраняется как межплатформенная страховка от silent event loss.
- Перенос scan в фон не ускоряет применение snapshot. Следующая оптимизация — batch/apply без
  потери порядка событий.

## WebP scheduling

- В проверке 288 конфигураций per-segment budget остановил 82 случая с oversized rounded
  segment.
- Aggregate-only превышений поверх conservative `worker_limit` в этой сетке не найдено.
- CAS reservation нельзя удалить без единого расчёта frame rounding, split и worker cost.
- Permanent normalize/validate и panic прекращают попытки. Budget resource остаётся
  retryable.

## Слоты провайдеров

- Лимит пула ограничивает одновременные запросы к моделям через подключения этого пула, а не
  задачи очереди. Пулы очереди постоянные и лимиты не повторяют.
- Пулов по умолчанию нет. Провайдер без пула слот не берёт. Внутри ключа очередь строго FIFO;
  интерактивного обгона нет.
- Удаление пула отпускает его ждущих без слота; уже выданные слоты дорабатывают.
- Список моделей, проверка модели и pull Ollama тоже занимают слот пула.
- Поиск и чтение страниц имеют отдельный лимит в настройках, общий для обоих инструментов.

## Хранилища и кэши

- Thumbnail atlas остаётся: корректное end-to-end сравнение с отдельными JPEG не показало
  достаточной выгоды для смены storage model.
- SQLite остаётся: snapshot/JSON не доказал эквивалентность query, incremental update и recovery.
- Потеря перестраиваемого cache допустима, но потеря пользовательского результата — нет.

## Изоляция Windows от песочниц агентов

Песочницы LLM-агентов на Windows меняют права на рабочем каталоге и не снимают их после работы.
Подтверждено для OpenAI Codex (`CodexSandboxService`, группы `CodexSandboxUsers`,
`CodexSandboxOnline/Offline`). Другие песочницы, AppContainer и инструменты, которые ставят
метку Low integrity, дают тот же эффект. Остановка процесса или удаление песочницы права не
возвращает: они записаны в файловую систему.

Главный механизм — метка целостности Low на корне репозитория (`Mandatory Label\Low Mandatory
Level:(OI)(CI)(NW)`). Она наследуется на все файлы, включая exe в `target`. Windows запускает
процесс с уровнем не выше метки его exe, поэтому всё, что запускается из рабочего дерева,
работает на Low и не может писать в каталоги уровня Medium: `%TEMP%`, `%LOCALAPPDATA%`,
`Documents`. Писать внутрь дерева при этом можно: там та же метка Low.

Признаки (отказ в доступе только у процессов, запущенных из дерева):
- сборка: LNK1104 на `%TEMP%\lnk{GUID}.tmp` у `lib.exe`, `UnauthorizedAccessException` на
  `%TEMP%\MSBuildTemp<GUID>` у MSBuild, код 2 без сообщения у `cl.exe`. Падают build-скрипты
  `cc`/`cmake`: `build-script-build.exe` лежит в `target`;
- запуск: exe из `target` не пишет в `Documents` и `%LOCALAPPDATA%`; SQLite не создаёт WAL
  (на экране код 14);
- та же сборка с `CARGO_TARGET_DIR` вне репозитория или копия exe вне дерева работают.

Ловушка диагностики: перенаправление `TEMP` внутрь `target` «чинит» сборку, потому что там тоже
Low, и маскирует причину. Обходы (`TEMP` в дереве, запуск копии exe снаружи, отключение
debug info) не добавлять, пока не проверена метка.

Диагностика:

```powershell
icacls <repo>                          # ищем "Mandatory Label\Low" и чужие SID/группы
icacls <repo>\target\debug\build\<crate>-*\build-script-build.exe   # (I)…Low…(NW)
```

Исправление (снимает и DACL-записи песочницы, и метку). Сначала сохранить текущие права:

```powershell
icacls <repo> /save <вне-repo>\acl-backup.txt /C /Q
icacls <repo> /reset /T /C /Q
icacls <repo> /setintegritylevel "(OI)(CI)M" /C /Q
```

`/reset` метку не трогает, нужна вторая команда. После неё проверить, что exe в `target` показывает
`Medium`. Песочница поставит метку снова, если её опять запустить в этом каталоге. Подробности
расследования 28.10.26 — в [windows-build.md](tasks/windows-build.md).

`scripts/windows/run.ps1` запускает копию exe из `%LOCALAPPDATA%\mediaa\dev-run`. Этот обход
появился из-за той же метки. Пока метка снята, он не обязателен.

## Сборка и проверки

- FFmpeg статически связывается через vcpkg; команды требуют окружения из Windows scripts.
- Инференс только внешний. Приложение не линкует llama.cpp, Vulkan и sherpa-onnx и не
  запускает команды пользователя. Файл для OpenAI `/audio/transcriptions` не больше 25 МБ.
  Без диаризации окно расшифровки около 600 с, с диаризацией около 480 с. Диаризация ролика
  выключена, пока её не включили, и молчит, если она выключена у модели речи.
- Отказ в доступе к `%TEMP%` у `lib.exe`, MSBuild или `cl.exe` во время сборки сначала проверять
  на метку Low (раздел «Изоляция Windows от песочниц агентов»).
- Windows snapshot baselines не являются доказательством поведения Linux/macOS.
- Live tests реального desktop/capture пропускаются без display session.
- Documentation-only изменение не требует повторного Rust suite.
