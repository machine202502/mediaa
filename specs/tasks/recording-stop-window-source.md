# Окно после остановки записи зависит от источника старта

## Правило

- Запись начата **из окна** → после остановки (UI, горячая клавиша, трей) приложение
  возвращает окно из трея.
- Запись начата **из трея** → остановка не показывает, не скрывает и не фокусирует окно.
- Источник остановки больше не меняет это решение.

## Исправление

`stop_recording_from_source` больше не перезаписывает `recording_quiet` по источнику остановки.
Флаг выставляется только при старте:

- UI/hotkey-старт → `false`;
- старт из трея → `true`;
- региональная запись через overlay → по `restore`.

Поэтому UI-старт с включённым «Скрывать в трей во время записи» скрывает окно на время
записи, но после остановки любым способом возвращает его.

## Тесты

- `stop_from_tray_uses_the_same_save_flow` — трей-старт: окно не меняется.
- `stop_from_tray_restores_a_window_recording_even_after_hide_to_tray` — старт из окна с
  `hide_to_tray = true`, остановка из трея → окно возвращается.
- app: **264**.
