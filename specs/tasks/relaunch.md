# Повторный запуск открывает существующий UI

Статус: готово (02.11.26).

## Поведение

- Если демон не запущен, лаунчер поднимает его и UI.
- Если демон запущен, но UI нет — лаунчер запускает UI.
- Если UI уже открыт — новый процесс UI не создаётся. Лаунчер просит демон
  отправить существующему UI событие `tray: show_window`; UI вызывает
  `show_window`: снимает minimized/скрытие и фокусирует окно.
- `--area` при открытом UI просит его открыть region picker, а не поднимает второй UI.
- `--tray` (автозапуск) по-прежнему не показывает окно.

## Как устроено

`Launcher` получает в `Welcome` metadata `ui=true/false`. Если `ui=true`, он шлёт
команду `show_window` (или `picker_starting`) и завершается; daemon превращает её
в tray-событие существующего UI. Если `ui=false`, лаунчер запускает UI как раньше.
Второй UI-процесс, подключившийся напрямую, по-прежнему получает `Reject`.

## Проверка

- повторный запуск при открытом UI: процессов остаётся два (daemon + UI), окно
  становится `Visible=True` (проверено `list-windows.ps1` в background-режиме);
- повторный запуск без UI: поднимается ровно один UI;
- `cargo test -p mediaa --lib`, clippy.
