# Реструктуризация проектной документации

## Статус

Работа выполняется 26.10.2026. Исходная структура проектной документации заменяется каталогом
`specs/`.

## Цель

Сделать проектную документацию пригодной для человека и LLM:

- отделить общие принципы решений от обязательных правил;
- описать текущую архитектуру без исторических вариантов;
- собрать важные ограничения и причины их существования;
- хранить контекст каждой задачи рядом со ссылкой из общего прогресса;
- позволить другой модели начать работу только по связанному task-документу, когда он достаточно
  подробен;
- не смешивать законы проекта, наблюдения о платформах и конкретную реализацию.

## Решение

Создаются:

```text
specs/
  principles.md
  rules.md
  architecture.md
  constraints.md
  progress.md
  tasks/
    documentation-restructure.md
    architecture-simplification.md
    ui-regression.md
    performance.md
    repository-maintenance.md
```

Старый каталог удаляется после переноса актуальных знаний и обновления всех ссылок.

## Что сохранить

- общие принципы из прежних инструкций;
- явные пользовательские правила;
- полезные повторяемые проверки;
- подтверждённые ограничения;
- фактическую архитектуру;
- решения и результаты performance/architecture задач;
- исторические группы задач в сжатом виде, достаточном для понимания причин решений.

## Что удалить

- старые конкурирующие планы как активные инструкции;
- `stones.md` и `practices.md` как отдельные источники истины;
- старые ссылки в `AGENTS.md`, `CLAUDE.md`, README и project skills;
- устаревшие необработанные audit-файлы.

## Критерии готовности

- поиск по старому имени каталога не находит активных ссылок;
- каждый ID в `specs/progress.md` имеет ссылку на task-документ;
- `specs/architecture.md` соответствует текущему дереву `crates/`;
- `specs/constraints.md` объясняет мотивацию ограничений;
- `CLAUDE.md` и `AGENTS.md` описывают новый процесс;
- project skills не ссылаются на удалённые документы;
- Rust-код не изменялся, поэтому проверка ограничивается Markdown-ссылками, инвентарём файлов и
  `git diff --check`.
