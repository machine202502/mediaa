# Просмотрщик: backpressure кадров

## Причина лагов

`Player` запускал `preview_frames` без обратной связи: воркер декодировал видео с максимальной
скоростью, а в bounded-канал (8 кадров) писал через `try_send`, игнорируя `Err`. Когда канал
заполнялся, кадры молча выбрасывались, а декодер продолжал работать на полную мощность.

Для 30-секундного 1080p MP4 это означало: декодер проходил весь файл за ~2.5 с, загружал CPU,
оставлял в очереди только последние кадры, а плеер показывал рывки/лагал. Обычный плеер
декодирует с реальной скоростью, поэтому у него файл «летает».

## Исправление

Отправка кадров в `Player` теперь блокирующая с таймаутом:

- `frames.send_timeout(frame, 20ms)`;
- при заполненной очереди декодер ждёт, пока UI заберёт кадр;
- при отмене/смене поколения цикл сразу выходит;
- декодер не уходит больше чем на 8 кадров вперёд.

Так декодирование идёт в темпе просмотра, без CPU-шторма и без выбрасывания кадров.
