# Документация UI-примитивов, тем и настроек

## Цель

Зафиксировать в `specs/architecture.md` три архитектурных факта, которые нужны для безопасного
изменения UI:

- переиспользуемые виджеты находятся в `crates/app/src/widgets/`;
- описания тем и палитр находятся в `crates/app/src/themes/`;
- пользовательские настройки и данные приложения хранятся в известных путях.

## Контекст

В приложении уже есть отдельные каталоги `widgets/` и `themes/`, а `settings_writer` сохраняет
настройки вне UI. Архитектурный документ всё ещё ссылался на старый `theme.rs` и не описывал
границы этих каталогов и расположение пользовательского TOML.

## Решение

- Добавить в раздел `app` подразделы про reusable widgets, themes и user settings/data.
- Для виджетов указать правило: один виджет — один файл, общие примитивы только в `widgets/`,
  страницы содержат только композицию.
- Для тем указать `themes/mod.rs` как владельца контрактов `Palette`/`IconPalette` и по одному
  файлу на тему; новая тема добавляется файлом и реэкспортом.
- Для настроек указать `~/.mediaa.toml`, legacy-миграцию из `ProjectDirs::config_dir()`,
  атомарную запись через `SettingsWriter`, каталоги `logs/` и `work/`, отдельное хранение ключей
  провайдеров в OS keychain.

## Затронутые файлы

- `specs/architecture.md`
- `specs/progress.md`
- `specs/tasks/ui-docs-widgets-themes-settings.md`

## Проверка

- Проверить существование всех указанных каталогов и файлов.
- Сверить путь настроек с `core::paths::settings_file()` и legacy-путём.
- Проверить, что в архитектуре не осталось ссылки на удалённый `theme.rs`.
- Documentation-only изменение не требует Rust suite.

## Риски

Нет изменений поведения. Риск только в устаревании путей: при переносе `widgets/`, `themes/` или
файла настроек архитектурный документ нужно обновить в том же изменении.
