# Repository и project skills

## Статус

Начальная настройка выполнена; документ поддерживается при изменении процесса разработки.

## Контекст

Проект развивается LLM-агентами. Последовательный процесс задач оказался проще прежней
оркестрации и исторических журналов. При этом обязательные операционные правила нельзя
смешивать с архитектурными фактами и редкими техническими ограничениями.

## Решение

- Пользователь задаёт текущую цель; текущая цель имеет приоритет над памятью.
- Работа идёт по одной строке `specs/progress.md`.
- Контекст задачи находится в `specs/tasks/*.md`, а не в общем списке.
- `specs/principles.md` хранит способы принимать решения.
- `specs/rules.md` хранит обязательные пользовательские и рабочие правила.
- `specs/architecture.md` хранит текущую архитектуру.
- `specs/constraints.md` хранит важные ограничения и мотивацию.
- Model skills `$mediaa-audit` и `$mediaa-complexity` находятся в `.agents/skills/`.
- Claude Code wrappers находятся в `.claude/skills/`.
- Коммиты создаются только после явного разрешения на конкретную партию изменений.

## Проверка документов

- поиск по старому имени каталога документации;
- `rg --files specs`;
- проверить, что каждый ID в `progress.md` ссылается на существующий task-документ;
- `git diff --check`.

## Ограничение

Task-документ не является отдельным законом. При конфликте действуют текущее указание
пользователя, `specs/rules.md`, `CLAUDE.md`, затем проверенные код, тесты и
`specs/constraints.md`.
