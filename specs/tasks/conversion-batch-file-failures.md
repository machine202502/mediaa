# Неуспешный файл в пакетной конвертации

## Цель

Если один файл пакета не удалось прочитать или сконвертировать, статус `Failed` получает только
он, а остальные файлы конвертируются дальше. Причина неуспеха конкретного файла видна в подсказке
у значка статуса.

## Причина

`ConversionController::poll_probe` при ошибке чтения текущего файла оставлял `probed = Err(...)`.
`ui/pages/convert/controller.rs::ui_inner` в этом состоянии не показывал ни форматы, ни выбранную
цель, а `can_start` требовал `target`, поэтому пакет останавливался: `batch_auto` не снимался,
кнопка «Конвертировать» была недоступна, остальные файлы не обрабатывались. В подсказке у крестика
был только общий текст «Не сконвертировано», причина (`BatchItem::error`) не показывалась.

## Решение

- `poll_probe` при ошибке чтения текущего файла вызывает `skip_failed_input`: файл получает
  `BatchStatus::Failed` и текст ошибки, из очереди берётся следующий, а текущий вход сбрасывается.
  Пакет не останавливается; когда файлы кончились, `batch_auto` снимается.
- Файл с неподдерживаемым форматом (`MediaKind::detect` == `None`) проходит тем же путём: он
  помечается `Failed` и пропускается, а не блокирует весь пакет.
- `set_current` теперь всегда сбрасывает `probed`: следующий файл сначала проверяется, и только
  после успешной проверки запускается его конвертация. Это убирает гонку между ошибкой проверки и
  запущенной конвертацией, когда `probed = Err` блокировал следующий файл.
- Подсказка у значка `Failed` берёт `BatchItem::error` (ошибка проверки или конвертации), общий
  текст остаётся запасным вариантом.
- Если для текущего файла уже запущена конвертация, проверка не пропускает его: исход решает сама
  конвертация, иначе файл можно было бы посчитать дважды.

## Затронутые файлы

- `crates/app/src/logic/conversion/mod.rs` — `skip_failed_input`, `current_input_failed`,
  `set_current`, `poll_probe`;
- `crates/app/src/ui/pages/convert/controller.rs` — текст подсказки статуса;
- `crates/app/src/logic/conversion/tests.rs` — тесты пропуска битого и неподдерживаемого файла;
- `crates/app/src/shell/ui_tests.rs` — сквозной тест пакета с отсутствующим файлом и подсказкой.

## Проверка

- `a_missing_batch_file_fails_alone_and_the_batch_moves_on` — отсутствующий файл получает `Failed`
  с ошибкой, текущим становится следующий, его проверка успешна;
- `an_unsupported_batch_file_is_skipped_too` — неподдерживаемый файл пропускается;
- `convert_page_fails_a_missing_file_alone_and_converts_the_rest` — на странице «Конвертировать»
  пакет из отсутствующего и существующего PNG: первый остаётся `Failed`, второй становится `Done`,
  JPEG создаётся, а наведение на крестик показывает сохранённую причину;
- `cargo test -p mediaa --lib` — 389 passed;
- `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets`.

## Материальные риски

- Каждый следующий файл пакета теперь ждёт свою проверку перед запуском конвертации: пакет идёт
  чуть медленнее, но битый файл больше не запускает заведомо провальный job.
- Кнопка «Конвертировать» по-прежнему перезапускает и уже упавшие файлы (`prepare_batch_run` берёт
  все не-`Done`), это существующее поведение «повторить всё».
- Красная строка ошибки под списком остаётся для текущего файла, у которого не прошла проверка.
