# Ленивые превью для WebP/GIF

## Решение

- Сетка библиотеки больше не запускает генерацию MP4-прокси для каждой анимации. Миниатюры
  декодируются из исходного WebP/GIF и показываются сразу, без ожидания прокси и без крутилки.
- Плеер при открытии анимации:
  - если MP4-прокси уже готов — использует его;
  - если нет — сразу играет исходный WebP/GIF и запускает генерацию прокси в фоновом потоке
    `viewer-proxy`, не блокируя показ.
- `preview_frames` снова только читает `ready_proxy`: синхронной генерации в пути кадра нет.
- Фоновой поток `previews` в `Thumbnails` оставлен только для удаления устаревших прокси.

## Файлы

- `crates/app/src/features/library/thumbs.rs` — убран `ProxyMsg::Ensure` при показе миниатюр.
- `crates/app/src/features/library/player.rs` — фоновый `ensure_proxy` при открытии анимации,
  выбор готового прокси для воспроизведения.
- `crates/media/src/preview.rs` — только `ready_proxy`, без ленивой генерации в кадре.
