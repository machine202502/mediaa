# Ошибки NAL при построении preview для WebP

## Где используются preview

MP4-прокси из `<медиа>/.cache/previews` используются в двух местах:

- сетка библиотеки — `thumbnail()` берёт `ready_proxy(path)`;
- просмотрщик — `Player` передаёт в `preview_frames()` путь воспроизведения, который теперь
  явно выбирается как готовый прокси, а не исходный WebP.

`preview_frames` не создаёт прокси синхронно: если готового MP4 ещё нет, библиотека и плеер
показывают исходный WebP/GIF, а прокси строится в фоновом потоке превью. Как только MP4 готов,
следующее открытие использует его.

## Что означали ошибки

`Packet corrupt`, `Invalid NAL unit size`, `missing picture in access unit` появлялись после
сохранения WebP. Это был не fallback и не порча итогового файла: финальный WebP уже был записан
и проходил probe/декодирование.

Ошибки возникали при построении preview-прокси: в `ensure_proxy_for` передавался промежуточный
**склеенный MKV**, а preview-энкодер читал его H.264. Склейка чанков через concat demuxer на
границах даёт неидеальный битстрим, поэтому FFmpeg писал такие предупреждения. Для live-WebP
этот MKV вообще не нужен — итоговый WebP уже готов.

## Исправление

- Для анимаций (WebP) preview строится **из финального файла**, а не из промежуточного MKV:
  `ensure_proxy_for(&out, &out, cancel)`.
- Это сделано и для live-пути, и для offline-пути.
- Для обычного видео preview не создаётся этим путём.
- `Player` выбирает готовый прокси до запуска видео-воркера; если прокси нет, воспроизводится
  исходный WebP/GIF без ожидания и без крутилки.
