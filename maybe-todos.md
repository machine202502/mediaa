## 1. Проект в двух словах

* **MediaA** — настольное приложение на Rust: egui 0.36 + wgpu, Windows в первую очередь.
  Собирается в **один статический exe**. Разделы: Библиотека, Захват, Конвертация, Агент.
* Раздел **Агент**:
  * каталоги аудио и видео, у каждого файла вкладка-«студия» с панелями Диалог · Видео · Чат;
  * распознавание речи и диаризация (sherpa-onnx);
  * гибридный поиск по записи (FTS5 + эмбеддинги + реранкер);
  * главы со сводками (outline);
  * чат с агентом-инструментальщиком по одной записи или по папке;
  * поиск в интернете.
* Пользователь общается **по-русски**, ответы — по-русски. Интерфейс тоже на ru/en: оба
  языка в `crates/app/locales/{ru,en}.toml`, каждый ключ должен быть в обоих.
* **Правила проекта (CLAUDE.md):**
  * никакой обратной совместимости: ни миграций, ни шимов, ни версий настроек;
  * неиспользуемое удалять, включая ключи локализации;
  * предпочитать зрелые крейты;
  * всё покрывать тестами;
  * перед завершением прогонять `cargo test --workspace` и
    `cargo clippy --workspace --all-targets`.
* **Ограничения от пользователя:**
  * не слать глобальные нажатия клавиш (SendKeys запрещён), PostMessage — только своим окнам;
  * не убивать чужие процессы: только свои PID, например записанный в `/tmp/mediaa.pid`;
  * не смотреть чужие окна;
  * установка ПО — только с разрешения;
  * API-ключи хранятся в системном хранилище паролей (крейт `keyring`, `core::secrets`),
    никогда в `settings.toml` или файлах;
  * email пользователя никуда не отправлять.
* Пользователь не любит, когда на вопрос «объясни» сразу пишут код: **на вопрос — ответ,
  код — только по согласию**.

## 2. Сборка, запуск, тесты

```bash
export VULKAN_SDK="C:/VulkanSDK/1.4.363.0"
export LIBCLANG_PATH="C:/Program Files/Microsoft Visual Studio/18/Community/VC/Tools/Llvm/x64/bin"
cargo build --release -p mediaa
cargo test --release --workspace
cargo clippy --release --workspace --all-targets
```

* llama.cpp (`llama-cpp-2` 0.1.159) собирается с Vulkan; `vulkan-1.dll` подгружается
  отложенно. Файл `Directory.Build.targets` (`BuildInParallel=false`) лечит гонку MSBuild
  в `vulkan-shaders-gen`, удалять его нельзя.
* FFmpeg — статический, через vcpkg (`x64-windows-static-release`), `+crt-static`.
* В Git Bash нет Python (только заглушка Windows Store). Многострочные правки Rust делать
  через Edit: perl и sed портят `\n`, `\\` и `@{}`.

### Запуск для проверки UI

```bash
S=<scratchpad>; MEDIAA_DEV_LIBRARY="$S/lib" ./target/release/mediaa.exe --page=queue & echo $! > /tmp/mediaa.pid
cargo run --release -q -p mediaa-platform --example snap -- "$S/out.png" MediaA
kill $(cat /tmp/mediaa.pid)
```

* `--page=` принимает library, record, providers, queue, budget, models, catalogs и другие
  страницы (см. `page_from_args` в `app.rs`).
* `MEDIAA_DEV_OPEN` открывает файл, а если передать имя папки — чат этой папки.
* `MEDIAA_DEV_ASK` один раз задаёт вопрос в открытом чате.

Пользователь сам запускает **debug**-сборку `target\debug\mediaa.exe` со своей библиотекой
`C:\Users\wmachine\Documents\MediaA`. Его процессы не трогать.

## 5. Задачи

Объём: **S** — до пары часов, **M** — около дня, **L** — больше.
Рекомендуемый порядок: 4.1 → 4.2 → 5.1 → 5.2 → 5.3 → 5.4 → 5.5 → 3.5 → 1.2 → 1.1 → остальное.

### 5.1 Распознавание речи: разные форматы моделей (M) — пользователь интересовался

* **Сейчас** [speech.rs](crates/agent/src/speech.rs) (`model_files`) понимает только раскладку
  sherpa-onnx и только два типа NeMo:
  * CTC: `model*.onnx` + `tokens.txt`;
  * transducer: `encoder*`/`decoder*`/`joiner*` + `tokens.txt`.
* **Ловушка:** Zipformer-трансдьюсер тоже состоит из encoder, decoder и joiner. Он будет
  принят за NeMo (`model_type = "nemo_transducer"`) и запущен неправильно.
* **Сделать:**
  1. Определять семейство по файлам и метаданным ONNX: Whisper (`*-encoder.onnx` +
     `*-decoder.onnx` + `*-tokens.txt`), SenseVoice, Zipformer transducer и CTC, Paraformer,
     Moonshine, Canary, Parakeet, FireRedASR, Dolphin, Omnilingual. В крейте `sherpa-onnx`
     1.13.8 уже есть все конфиги (`Offline*ModelConfig`).
  2. Для каждого семейства заполнять свой конфиг в `Recognizer::load`.
  3. Давать понятную ошибку для неподходящей папки: какой формат нужен, кнопка ↺ (вернуть
     умолчание), примеры репозиториев `csukuangfj/sherpa-onnx-*`.
  4. Тесты: определение семейства по набору имён файлов (без сети) и один живой
     игнорируемый тест на маленькой модели (Whisper tiny или Zipformer).
* **Не делать** onnx-asr (`istupakov/*`), faster-whisper и whisper.cpp:
  * у onnx-asr другой препроцессинг и нет метаданных sherpa-onnx;
  * whisper.cpp конфликтует по символам ggml с llama.cpp в одном статическом exe.
* **Контекст:** у пользователя в настройках был `istupakov/gigaam-v2-onnx` — проверка
  написала «no tokens.txt (not a sherpa-onnx model)». Умолчание:
  `csukuangfj/sherpa-onnx-nemo-ctc-punct-giga-am-v3-russian-2025-12-16`.

### 5.2 Диаризация отдельной задачей очереди (M) — пользователь спрашивал

* **Сейчас** диаризация — вторая половина задачи `transcribe`
  ([transcribe.rs](crates/agent/src/transcribe.rs), `run`). Отметка `cursor.recognized`
  разделяет этапы, полоса прогресса делится 85/15. Минусы:
  * прогресса нет: `OfflineSpeakerDiarization::process` в Rust-обёртке без колбэка;
  * нельзя прервать посередине;
  * нельзя перезапустить отдельно (например, с заданным числом говорящих);
  * звук декодируется заново;
  * ошибка диаризации роняет всю задачу.
* **Сделать:**
  * новая задача `diarize`; цепочка `transcribe → diarize → index → outline`;
  * `transcribe` в конце ставит `diarize`, если выбрана модель диаризации, иначе сразу `index`;
  * при ошибке диаризации реплики остаются без говорящих, а `index` всё равно ставится;
  * в студии кнопка «Определить говорящих» с полем «сколько человек»
    (`Input.speakers` уже есть, передаётся в `FastClusteringConfig.num_clusters`);
  * прогресс — через C API `SherpaOnnxOfflineSpeakerDiarizationProcessWithCallback` из
    `sherpa-onnx-sys`, если он доступен, иначе показывать этапы;
  * локализация ключей задачи в очереди; тесты.

### 5.3 Поиск по записи (идеи из docs/agent.md §8), по S каждая

1. **Расширение коротких находок:** найденная реплика «Да» или «Согласен» дополняется
   соседними репликами перед выдачей модели (`agent/src/search.rs` или `assistant/tools.rs`,
   инструмент `search`).
2. **Имя говорящего в вопросе:** «что Антон говорил о сроках» → параллельный поиск только
   по репликам этого говорящего. Не жёсткий фильтр. При неоднозначном имени агент
   переспрашивает.
3. **Уточняющие вопросы:** «а что она сказала про сроки?» переписывается в самостоятельный
   запрос по истории чата до поиска.
4. **Фильтр по времени:** «в начале», «после 30-й минуты» → ограничение диапазона.
   Сейчас этого нет совсем.

### 5.4 Агент

* **Охрана места под ответ (S):** гарантировать ≥ 20 % контекста под ответ; длинные куски
  резать посередине. Сейчас есть только сжатие старых результатов при 60 %
  (`compact` в `assistant/mod.rs`).
* **Отбор инструментов по смыслу (S):** инструментов уже ~15 вместе с веб-инструментами.
  Для маленького контекста отдавать модели только подходящие (близость эмбеддингов
  к вопросу).
* **Самопроверка длинных отчётов (M):** после разделов `say` отдельный проход модели-
  помощника сверяет отчёт с найденными фактами.
* **Параллельные `delegate` и части скана (M):** при модели провайдера — параллельно
  в пределах слотов «provider calls». Сейчас всё по очереди.
* **Выбор моделей с запасом (M):** лёгкие запросы — маленькой модели, тяжёлые — большой
  или облачной. Упавший или упёршийся в лимит провайдер временно отключается, запрос уходит
  следующему.
* **Лимиты на инструмент (S):** «не чаще N раз за ответ», в дополнение к отпечаткам вызовов.
* **`recall` (S):** поиск по памяти чата. Сейчас все факты целиком в промпте.
* **Слоты на каждого провайдера (S):** сейчас лимит «provider calls» общий.

### 5.5 Качество (по прогонам)

* **Ответы из собственных знаний.** Модель отвечает без поиска, как было с вопросом «что
  такое СТД-Р». Идея (S/M, эвристика, аккуратно): если в ответе есть утверждения без цитаты
  `[m:ss]` и без ссылки на прочитанную страницу, один раз вернуть модели с просьбой
  подтвердить их.
* **Tavily `include_raw_content`.** Брать текст страницы сразу из поиска: JS-сайты
  (Госуслуги) тогда дают текст.
* **Подсказка про DuckDuckGo** на карточке: прямо советовать Tavily или Brave + прокси.
* **Скорость на встроенной видеокарте:** кешировать начало промпта между шагами (KV-cache
  prefix в `local.rs`/`brain.rs`), меньший контекст по умолчанию, совет перенести тяжёлые
  задачи на провайдера.

### 5.6 Имена говорящих (остаток P2)

* **Автопредложение имён (M):** после `index` (рядом с `outline`) модель читает места, где
  люди представляются или обращаются друг к другу. Предлагает имя только с цитатой,
  в JSON по грамматике. Пользователь подтверждает в «Диалоге». Сейчас агент переименовывает
  говорящих только по просьбе в чате (`rename_speakers`).
* **Голоса между записями (M):** при переименовании сохранять эмбеддинг голоса (WeSpeaker)
  в таблицу библиотеки. В новой записи совпадения дают подсказку «похоже на X — принять?»,
  при высокой уверенности имя ставится сразу.
* **Пользовательский словарь (S–M):** сначала проверить hotwords в sherpa-onnx для CTC.
  Скорее всего их нет, тогда — правка текста после распознавания по словарю с нечётким
  сравнением.

## 6. Подводные камни, на которые уже наступали

* Маленькая модель путает `search` (по записи) и `web_search`. Описания инструментов и
  правило в промпте это уже различают. Не ослаблять.
* Большая страница из `web_read` вытесняла из контекста результаты скана, отсюда ответы
  «в видео ничего нет». Отсюда лимит `max_chars / 3` в `Web::new`.
* Первый шаг агента всегда смотрит в запись (`may_answer=false`); ответ — первый вариант
  `oneOf` в грамматике.
* Цикл генерации гасят DRY-сэмплер (разрывает только `"\""`) и `loop_start`. Обрезанный шаг
  повторяется до 2 раз.
* Скан кешируется в мета-данных записи под ключом `scan2:{parts}:{instr}`. Если менять
  формат скана, менять и ключ.
* В чате по папке голые длительности не превращаются в ссылки (`bare_times=false`).
* Загрузки с HF идут по одной (глобальный мьютекс). Спецификация `owner/repo/path/file`
  скачивает один файл.
* Настройки пользователя: `%APPDATA%\MediaA\MediaA\config\settings.toml`. Старые значения
  моделей из ранних версий там могут остаться: `Qwen/Qwen3.5-4B`, `istupakov/gigaam-v2-onnx`.
  По правилам проекта их не мигрировать: кнопка ↺ в «Моделях» возвращает умолчание.
